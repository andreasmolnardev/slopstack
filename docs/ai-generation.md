# AI generation

Set `STARBURST_LLM_BASE_URL`, `STARBURST_LLM_API_KEY`, and `STARBURST_LLM_MODEL` in the server environment to enable course generation via an OpenAI-compatible `/chat/completions` endpoint. If all three are blank, the server uses a deterministic fixture. Partial configuration is an error.

The provider path runs two stages: it first creates a curriculum outline containing prerequisites, knowledge units, and ordered modules/objectives; then it generates scenes and assessments against that outline. Validation checks bounds, IDs, knowledge references, exact module/objective preservation, scene and question counts, trusted widget types, timestamped caption bounds/order, objective alignment, and answer keys before publication. The learner's course goal and selected owner-checked source/concept snapshots are persisted in the generation job payload and included in both prompts so retries and startup recovery retain the same request context. The job also snapshots up to eight owner concepts with mastery below 0.6 so both stages can scaffold prerequisites and schedule review. Source selection is bounded to four sources and eight concepts, with source text truncated to 12 KiB per source and total context bounded to 36 KiB. Generated knowledge units are saved with course, module, and provenance references. The protected `/profile` screen saves interests, learning goals, prior knowledge, preferred language, default difficulty, target session length, narration, and captions. When a course-generation request omits difficulty or duration, the server uses the learner's saved defaults; generation snapshots these settings into its job context. The UI allows per-course overrides, and relevant interests, goals, prior knowledge, and language are included as untrusted learner context in both generation stages.

Generation jobs report progress through outline creation, outline validation, lesson generation, and final validation. They support polling, cancellation, startup recovery, up to three attempts with short backoff, graceful shutdown cancellation, duplicate request reuse, and a maximum of two concurrent generation workers. Never return provider credentials to the browser.

The deterministic fixture remains a short single-module example and does not call external services. Learner-history personalization and a live provider integration check are still outstanding; captions use the saved profile default; when narration is enabled, the player prepares an in-memory timeline on first playback and falls back to visual playback if Piper is unavailable. Generated narration is not persisted.
