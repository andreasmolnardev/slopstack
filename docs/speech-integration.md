# Speech integration

Piper and Whisper are optional external Wyoming TCP services. Set `STARBURST_WYOMING_PIPER_HOST`/`PORT` and `STARBURST_WYOMING_WHISPER_HOST`/`PORT` in the server environment. The backend uses the Wyoming `describe`/`info` round trip for service discovery, Piper `synthesize`, and Whisper `transcribe` over TCP; Piper audio chunks are assembled as WAV. Health responses report service discovery latency and advertised TTS model names, language tags, installation state, descriptions, and speaker options. The authenticated lesson player, Audio Studio, and speaking-practice pages allow selecting an advertised voice and speaker and report when the service is disconnected or does not expose voice choices. The learner profile saves the default lesson voice and speaker; each endpoint can still choose a session-specific value. Actual speech requests remain the functional test for a voice; discovery alone does not prove synthesis. Whisper uploads currently accept PCM 16-bit mono/stereo WAV from 8–96 kHz, capped at 20 MiB, and send the raw PCM samples to the Wyoming service. The browser calls authenticated Starburst API endpoints and never connects to Wyoming directly. Audio is streamed through requests and is not persisted. Protocol fixture tests pass, but no live speech service is configured, so live discovery, synthesis, and transcription remain unverified. Audio Studio can play podcast turns sequentially using the selected voice, but uses the same voice and speaker for both roles and does not store an assembled episode. Language speaking practice captures mono PCM WAV or accepts an upload, sends it to Whisper, and compares the transcript to an owned English vocabulary word. Feedback is transcript-based and does not score accent or pronunciation quality. Persistent settings for multiple endpoints, audio caching, media normalization for WebM/other formats, and persistent audio assets remain unimplemented.
